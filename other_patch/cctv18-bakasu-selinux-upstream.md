# CCTV18 + BakaSU upstream SELinux integration (v3)

The dedicated 6.12.23 workflow pins BakaSU d5e9e025b8b49155f8014684d64c91742b465f65 and CCTV18 susfs4oki 5f236a7b573c5a21ad0e5871ee96b63b89486596. The device kernel, toolchain and all CCTV18 filesystem/device adaptations remain. Both earlier v2 patches are no longer applied by this workflow. Other workflows are unchanged.

CCTV18 currently embeds independent SELinux handlers. The follow-up patch restores the native selinux_lsm_setattr and sends app attr/current writes to BakaSU my_setprocattr (the SUSFS macro alias of ksu_handle_selinux_setprocattr). This uses the driver's new dual-policy parser and all its credential/transition checks. App selinuxfs context/access requests likewise use BakaSU my_write_context/my_write_access; other callers use the original kernel handlers. The status page fast path reads fake_status without the redundant mutex (KernelSU #3945, BakaSU a90ac6f), and the real status page is obtained only on fallback. No SELinux permission is removed. CCTV18 helper definitions remain for compatibility but these three app entry paths no longer use the independent parser.

Validation: apply the pinned CCTV18 SELinux patches to actual android16-6.12-2025-06 source, apply the adapter with fuzz=0 and compare output; extract the pinned driver's real handler into the C stub harness. CI repeats the forwarding/permission/status assertions and functional C cases before compilation, and checks final CONFIG_KSU_SUSFS=y with tracepoint hook disabled. These tests do not prove real-device timing or detection results. Test boot, root, SUSFS, original kernelsu detected and Duck Detector timing after flashing. An undocumented detector cannot be identified from these changes alone.

The driver compatibility stop is absent upstream at the pinned revision; no local build-stop bypass is needed. Patch application failure is fatal. The full base SUSFS patch retains the existing fuzz tolerance of 3, but no longer ignores errors. The local adapter requires fuzz=0.
